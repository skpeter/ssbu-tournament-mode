# Design: In-match set scoreboard

Generated by /office-hours on 2026-10-23
Branch: main
Repo: skpeter/ssbu-tournament-mode
Status: APPROVED
Mode: Builder

## Problem Statement

The plugin already draws a top-center line, `SET 0-1 FT3`, and only while a match is running. The board the players need is different. From the request: show the player tags and the score, update that score when the game ends, keep it visible, put it on the bottom of the screen and horizontally centered, hide it when first-to is reached only after the results screen is finished, show it again at 0-0 when the next game starts, and hide it during the match if a fighter gets near or above it.

## What Makes This Cool

Each tag is drawn in that port's color, the score sits between them, and nothing animates. From across the setup you can see whose score is whose. The line gets out of the way when a fighter drops into the bottom of the screen. A second line of stages already played is the later version. It is not in this build.

## Constraints

- Audience is the two players looking at the game. Not an OBS or stream scoreboard.
- Draw with the existing imgui-smash callback in `src/score_overlay.rs`. Do not write vanilla HUD panes. A pane `set_text` on melee enter data-aborted (2168-0002). v1 hide uses world Y, not screen overlap. The original "near or above the scoreboard" line is the hardware gate in Success Criteria, not a second algorithm in this build.
- Do not call `world_to_screen` from fighter Main. smush_info crashed on the KO replay camera that way (`src/lib.rs` around the live-sample comment). `PostureModule::pos_x` during a guarded live sample is the read that plugin already treats as safe.
- Engine First to stays 1 Win. Set length stays in software (`FT2` / `FT3` in the ruleset name).
- No skyline-web toasts. `scoreboard = false` stays the kill switch.
- `libimgui_smash.nro` stays required. No new package.
- Target remains Smash Ultimate ≤ 13.0.4.
- If the tag read fails, the score still draws.
- Stage-history line is written down here and not built.

## Premises

1. Bottom-center on the game screen. Not OBS.
2. Change the existing imgui line. No HUD panes. No `world_to_screen` from fighter Main.
3. Visible on character select, stage select, the live match, and the results screen. Score updates when the game ends, so results shows the new score. Proximity hide runs only during the live match. After first-to, once results is finished, hide. The next game shows 0-0.
4. Tags use the same kind of versioned tag read smush_info has. Port color. No animation. Score survives a failed tag read.
5. First hide is a blunt bottom band, tuned on hardware. Stage line is not in this build.
6. Ship the plugin you already install, plus the overlay host it already requires.

## Cross-Model Perspective

Codex's cold read: the cool version is a quiet tag-score-tag ribbon that hides when fighters enter the bottom band and follows the set from character select through results. The line it quoted as the exciting part: "each player's tag in that port's color, score in the middle, no animation." It named the existing imgui draw (top-center at 960, 18, match-only) as the halfway point. Its weekend build matches this design: bottom strip, tag fallback, blunt hide, no animation, no stage line.

Codex also said the ribbon "disappears when the set is won." That is looser than premise 3. The board stays through the results screen and hides only after that screen finishes. Premise 3 stands.

## Approaches Considered

### Approach A: Patch the draw function in place

Move the window, change the string, and loosen the match-only gate inside `draw()`. Rejected: the show/hide timeline would live next to imgui calls, with no test for "stay on results" versus "hide after the set" versus "0-0 next game."

### Approach C: Mirror the game's own HUD visibility

Follow whatever pane the game already fades near fighters. Rejected: this plugin already data-aborted when it wrote a HUD pane. Reading that pane is an unproven cousin of that crash.

### Approach B: Tested visibility function, same draw

Chosen. A pure function decides show or hide. The draw callback only paints the decision. Same imgui host. v1 hide is a world-Y constant, not screen overlap.

## Recommended Approach

Add `src/board_visibility.rs` with no skyline imports. `draw()` in `src/score_overlay.rs` calls it. Position stays in the coordinate space the current window already uses (`x = 960` is horizontal center). Move the window to the bottom of that space, pivot `(0.5, 1.0)`, with a small margin above the edge. One auto-resize window. Inside it, three text calls, not one string:

- Left tag in the port 0 color. Skip the call if that tag is `None`.
- Score in a neutral color, `"{w0} - {w1}"`, on the same line. Spacing constant: 16 in overlay space.
- Right tag in the port 1 color. Skip the call if that tag is `None`.

Link `igPushStyleColor`, `igPopStyleColor`, and `igSameLine` beside the existing `igTextUnformatted`. No `SET` prefix and no `FT` label. The window pivot keeps the group centered when a tag is missing. Port colors are two constants in one place, tuned on hardware, until a live UI-color read is proven.

Build those three strings when wins change (`record_win` or the 0-0 reset) and when a tag changes from missing to present. `draw` copies the cache. It does not call `format!`. A host test asserts the cached score matches the wins after `record_win` and after the reset.

Wireframe (gray on purpose; real tags use port color): `C:\Users\samul\.gstack\projects\ssbu-tournament-mode\designs\scoreboard-sketch-20261023.png`

`Place` is one enum: `Menu`, `Css`, `Sss`, `Melee`, `Results`. There is no `results_finished` flag. "Results is over" means place changed away from `Results`.

```
enabled, set_length > 1, probe_ok?
        | no -> HIDE
        v yes
set_complete AND place != Results?
        | yes -> HIDE until the next melee enter resets to 0-0
        v no
place == Melee AND fighter in bottom band?
        | yes -> HIDE
        v no
place is Css, Sss, Melee, or Results?
        | yes -> SHOW
        v no (Menu)
        HIDE
```

`game_end` in `src/results.rs` currently calls `scoreboard::on_melee_leave()`, which hides the board at the moment the score updates. Stop using melee-leave as the hide.

Place changes, using hooks this crate already has. Do not add an `is_result_mode` offset in this build. `game_end` is not a melee enter.

- `game_end` attributes the win and sets place to `Results`. The board stays up.
- `game_exit` does not change place and does not hide the board.
- `CharaSelectScene` sets place to `Css`. `StageSelectScene` sets place to `Sss`.
- `MeleeRuleScene`, `MainMenuScene`, and `LocalTopScene` set place to `Menu` and keep today's full reset (wins 0, set not complete).
- Any other scene except `MeleeScene` sets place to `Menu`.
- The gap from `game_end` until one of those scenes is the results screen. This repo has no results scene name.

`record_win` already sets `SetPhase::Complete` as soon as a side reaches first-to, which is before results ends. Visibility must not key off `Complete` alone. The hide is `set_complete && place != Results`. On the results screen the final score stays up. On the next character select, place is `Css`, so the board hides.

Reset to 0-0:

- `MeleeRuleScene` and `MainMenuScene` keep today's full reset in `note_scene`.
- On `MeleeScene` enter, if `set_complete`, set wins to 0-0, clear complete, set phase to in-set, set place to `Melee`, then show. This covers both "came through character select" and "scene jumped straight from results into the match."
- On `MeleeScene` enter when the set is not complete, set place to `Melee` and keep the wins.
- Character select and stage select never reset wins.
- If a hardware run shows `0 - 0` on the deciding game's results screen, `MeleeScene` arrived too early. In that case the reset waits until place has been `Css`, `Sss`, or `Menu` since `game_end`. That guard is a hardware fix, not a second flag in the normal path.

Bottom band, v1 contract: link `smashline` from `https://github.com/HDR-Development/smashline.git` at rev `be3ef308ed8e479922da192a391e0684184af2af` (the commit smush_info's Cargo.lock already resolved). Sample with `Agent::new("fighter").on_line(Main, callback).install()`. The callback is `unsafe extern "C" fn(&mut SmashlineFighterCommon)`, the smashline 2 replacement for the old exec hook. Run the body only while `should_sample` is true: place is melee, the fighter is not dead, and the entry id is 0 or 1. `game_end` sets place to `Results`, so the sample stops for the results gap. Do not add a second flag. Game 2 is melee again after character select, and the band has to work there. Read `PostureModule` world Y. Do not call `world_to_screen`. The SD card must have one smashline runtime NRO, not both `libsmashline_plugin.nro` and `libsmashline_hook.nro` (that pair crashes after character select). If HDR or another pack already installed one, do not add a second. Document it next to `libimgui_smash.nro`. At boot, if both files are present under `sd:/atmosphere/contents/01006A800016E000/romfs/skyline/plugins/`, log once. Do not copy either NRO into this plugin. Two sample slots, entry 0 and entry 1. Each successful `should_sample` write stores that fighter's world Y and a frame stamp for that entry. Death, `should_sample` false, or place leaving `Melee` clears that slot. `in_band` hides only when a slot written this frame has `y < constant`. A cleared slot does not hide. A one-frame-old slot does not hide. The visibility function also ignores the band unless place is `Melee`, so a stale sample cannot hide character select. This is not screen overlap. A camera can put a high world-Y fighter over the board, or a low world-Y fighter in the middle of the screen. Success Criteria says when that constant has failed. The follow-up, not this build, is a screen-space sample from the imgui draw callback, skipped while place is Results, still never `world_to_screen` from fighter Main. That follow-up is tracked in `TODOS.md`.

Tags: a function that returns `Option<String>` from the same style of versioned UTF-16 tag read smush_info uses (`get_tag_of_player`). No panic. Wrong offset on 13.0.4 means empty tags and a visible score, plus a log line. Do not take smush_info's match feed, sockets, or replay dump. Reread both tags when place becomes `Css`. Rebuild the cached line if either string changed. Do not poll tags every frame. The score cache still rebuilds on `record_win` and on the 0-0 reset.

### Tests

Table-test `board_visible` in that file. Cases:

- Disabled, set length 1, or probe failed: hidden.
- Character select at 0-0: shown.
- Stage select at 1-0: shown.
- Live match, fighters clear: shown.
- Live match, band flag set: hidden.
- Band flag set but place is character select: shown (stale flag).
- Results after a non-deciding game: place `Results`, set not complete, shown.
- Results after first-to: place `Results`, set complete, shown.
- Character select after first-to: place `Css`, set complete, hidden.
- Next melee start after that hide: the reset helper sets wins to 0-0 and place to `Melee`, then `board_visible` shows. Assert the helper for the zeroing.
- Melee start while the set is not complete: wins unchanged.
- Melee start that skips character select after a finished set: wins 0-0.
- `game_end` with no later scene yet: place is Results, shown, including when the set just completed.
- Rules scene and main menu: hidden. Those scenes also keep today's full reset.

Run `cargo test --lib board_visible`. The crate is a skyline cdylib. If the host toolchain cannot link skyline, that failure is pre-existing. The new file imports nothing from skyline so the test is still the contract.

Three more pure helpers in the same file, same test command:

- `line_parts(tag0, tag1, w0, w1)` returns the pieces to draw. `None` omits that tag. Both missing still returns the score text. Empty string is treated as missing.
- `should_sample(place, dead, entry_id)` is true only when place is `Melee`, the fighter is not dead, and `entry_id` is 0 or 1. Results, character select, and any other entry do not sample.
- `in_band(y, constant)` is true only when `y < constant`. Equal to the constant does not hide.
- Band hide uses only slots stamped this frame. Cleared slot: show. One-frame-old slot: show. Both fresh and either under the constant: hide.

## Open Questions

- The tag offset smush_info uses is versioned, and that plugin's notes mention 13.0.5 defaults. Verify on ≤ 13.0.4. Until it is verified, ship the score anyway.
- The world-Y constant's numeric value. It is tuned on hardware. The algorithm is not open: v1 is world Y under that constant.

## Success Criteria

On hardware, one FT2 set, `scoreboard = true`, overlay host present:

- Character select of game 1 shows tags (or score alone if tags fail) and `0 - 0`, bottom-center.
- During the match, the line hides when either fighter's world Y is under the constant, and returns when both are at or above it. That is the v1 hide, not a screen-overlap test.
- If a low recovery still covers the line, or the line hides while both fighters are visually in the top half, record that the world-Y constant missed the original "near or above" request. Ship the rest of the board anyway. The screen-space follow-up is not this build, and v1 must not be described as screen overlap.
- Results shows the updated score. The line does not vanish at `game_end`.
- After a non-deciding game, character select and stage select still show that score.
- After the deciding game, once results is finished, the line is gone on the following character select.
- The next set's first match shows `0 - 0` again.
- `scoreboard = false` draws nothing.
- Set length 1 draws nothing.
- No toast, no pane write, no `world_to_screen` from fighter Main.

## Failure modes

- Stale band. A low sample that is not cleared would hide the line for the rest of the game. The plan clears the slot on death, on `should_sample` false, and on leaving `Melee`, and host tests cover a cleared slot and a one-frame-old slot. The player sees the line return. Covered.
- Stale tag. A tag edited on character select would stay wrong if tags were read once. The plan rereads both tags when place becomes `Css` and rebuilds the cache if either string changed. A tag change outside character select stays stale until the next character select. The player sees the old name. Handling exists for the chosen event.
- Stale score text. `draw` must not `format!`. If a win or the 0-0 reset forgets to rebuild the cache, the player sees the old score with no error. The host test that the cache matches wins after `record_win` and after reset is the lock. That test is part of this build.
- Deciding results shows `0 - 0`. `MeleeScene` during results would zero the score before results ends. No host test can prove scene order. The normal path still resets on that enter. The player sees `0 - 0`. The written repair is the wait until place has been `Css`, `Sss`, or `Menu` since `game_end`, applied after a hardware run shows the miss.
- World Y misses the board. A low recovery can cover the line, or the line can hide while both fighters are visually up high. The player sees that. Success criteria say to record it and ship the rest. The screen-space follow-up is the P2 TODO.
- Both smashline NROs. The game crashes after character select. Boot logs once if both files are on the card. The crash is loud if the log is ignored.
- Bad tag offset on 13.0.4. Tags are empty, the score still draws, and a log line fires once.
- `cargo test --lib board_visible` may fail to link this cdylib on the host. That failure is pre-existing. The new file imports nothing from skyline, so the test source is still the contract.
- `game_end` still reads stocks through `FighterInformation`. smush_info saw that kind of read crash the KO camera from fighter Main. This call site is different and unproven. This plan does not change attribution.

No failure mode is untested, unhandled, and silent. The two sharp misses are visible: `0 - 0` on the deciding results screen, and a world-Y hide that does not match the picture on screen.

## Parallelization

Sequential implementation, no parallelization opportunity. The visibility function, the place transitions, the draw, and the sample all land in `src/`. A second worktree on the same module would conflict. Write `board_visible` and its tests first, in that same lane, before the draw changes.
